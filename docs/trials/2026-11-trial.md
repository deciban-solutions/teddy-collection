# Live trials of `/teddy`, November 2026

Two live runs of the `/teddy` skill on 2026-11-15, each on a fresh video, in a test data home with the shipped two-watch example imported first. Both completed every step (0 to 11) and published privately. This record gives what each run cost, what it exposed, and what was done about it. The published pages are private and are not linked here.

## The runs

| | Trial 1 | Trial 2 |
|---|---|---|
| Video | "Hands-On with the Newest Rolex - The Perpetual Padellone" (uploaded 2026-09-15, 14:40) | "What $500 Buys You in Watches in 2026" (uploaded 2026-07-11, 22:29) |
| Type | single-watch review | unranked list, brand by brand |
| Watches recorded | 3 (one model in three variants) | 28 |
| Taxonomy | a provisional user branch of `shipped:dress@1` | `shipped:value@1`, unbranched |
| Comments downloaded / coded relevant | 797 / 224 | 738 / 138 |
| Outcome | completed | completed, then 11 wrong gallery photos corrected and republished (finding G1) |

Both runs used a stand-in interpreter that had the transcript library installed, put `yt-dlp` on the path, and substituted the plug-in root by hand, because the plug-in was not installed through the marketplace. None of that changes what the skill asks for.

## Cost (spec open question 3)

| | Trial 1 (review) | Trial 2 (list) |
|---|---|---|
| Wall time, skill as written | about 11 min 40 s | 18 min 21 s |
| Wall time with the photo correction | | about 21 min 10 s |
| Subagents | 3, all Sonnet (two coders, one audit coder) | 3, all Sonnet |
| Subagent time | 44 to 65 s each, about 66k to 69k tokens each | 66 to 85 s each, about 71k to 74k tokens each |
| Web searches | 10 of 60 | 35 of 60 (one per listed watch, seven for left-out candidates) |
| WebFetch calls | 16, several refused (403) or rate-limited (429) | 0; every price came from a search-result snippet |
| Script fetches by `verify-links` | not counted | about 120 over six runs |
| `/fact-check` or `/analyze` runs | none | none |

The answer to open question 3, for these two types: a single run fits well under half an hour and three subagents. A review costs about a quarter of the search budget; a long list uses over half of it and leaves no room to read price pages. Fetch volume, not search volume, is what drew rate limits, which is why the budget now has a fetch guideline. A contest, with its three blind scorers, was not trialled.

## Findings and what was done

Trial 1's findings are numbered F1 to F18 and trial 2's G1 to G18; eleven of trial 2's repeat trial 1's. F19 and F20 came from the owner's reading of the published pages. Each fix has a test that failed before it and passes after.

| Finding | Severity | Disposition |
|---|---|---|
| G1 Contact-sheet labels ran ahead of their frames, so 11 of 28 stills missed their watch | degrading (severe) | Fixed: each tile is extracted with the seek `frames still` uses, so a tile labelled t is the frame a still at t returns. Every still must now be opened and confirmed before `dataset-add` and carries `"checked": true`; `build-child` warns on any gallery photo without it. |
| F4/G2 A blocked site (401/403/429, 5xx, no response) read as "no source matched" | degrading | Fixed: `verify-links` reports such a source as `unreadable`, says so, and does not count it as a pass; the skill records "source blocked, unread" and tries the next rung. |
| F5/G3 Only the exact reference matched; ® broke model matches | degrading | Fixed: a page carrying the reference's core number (for example 53505 for M53505-0002) is a `partial` match; a model's words in order are a `tokens` partial; ® ™ © are ignored. |
| F3/G4 Confidence did not say what it grades; lists name families, not references | degrading | Fixed: confidence grades the reference when one is recorded, else the model; a family gets one record with `"family": true` and no reference. |
| F2/G5 Sheeting guidance assumed a contest | degrading | Fixed: Step 3.1 says which segments to sheet for each type and points at the description's chapters. |
| G6 A list's watches had no taxonomy for their own category | degrading | Fixed: a list's run category is its theme. |
| F7 The taxonomy additions file was undocumented and could not add `spec_fields` | degrading | Fixed: the format is documented with an example; a branch can add `spec_fields`, and a rule reading an unlisted field is refused. |
| F8 Peers with unreadable or foreign prices had no rule | degrading | Fixed: such a peer stays, with "not read" or the price unconverted and its currency named. |
| F9/G7 The coding brief was contest-shaped | degrading | Fixed: the brief and the counts now differ by type: agreement with the verdict and per-watch sentiment for a review; the selection and the watches named as left out for a list. |
| F12 A first run published the parent twice, once with photo-less watches | degrading | Fixed: the child is published first, the parent once, then the child is republished with its link back (the link is outside the frozen pages). The parent now finds photos of watches whose video is not yet registered. |
| G17 A long list leaves no budget to read prices | degrading | Fixed: the video's quoted price is primary; at most one price source per brand; snippet prices are labelled as such. |
| F19 The Rolex 1908 the review names was coded as a viewer subject but never recorded | owner finding | Fixed: a watch the video names is always recorded, with a photo, and a named peer is always in the landscape. A new `subject-check` (also run by `build-child`) refuses a coding subject with no recorded watch. Run against the two trial folders, it flags `rolex_1908` in trial 1 and nothing in trial 2. |
| F20 "Child set" wording on reader pages | owner request | Fixed: readers see "Video analyses", and the watch index says "Appears in". |
| G9 Re-adding a corrected photo duplicated it | cosmetic | Fixed: photos merge by path. |
| G16, F18 `verify-links` refetched everything; fetches were not budgeted | cosmetic | Fixed: `verify-links --only`; a 30-fetch guideline; a 429 host is skipped for the run. |
| F10/G8 κ of 1.00 or 0.00 over near-empty codings | cosmetic | Fixed: a field with fewer than five non-empty codings on either side has no κ, and the page says it was too few to measure. |
| F11 Free-text reason codes were uncitable keys | cosmetic | Fixed: folded into one `other` count. |
| F13/G12 Reading an artifact before every update | cosmetic | Fixed: no read for an artifact this session published; the parent relies on the Artifact tool's own conflict check. |
| G13 Large file maps in publish calls | cosmetic | Fixed: `publish-prepare` also prints a root and relative paths. |
| G14 The series check was an inline one-liner that failed on a read-only home | cosmetic | Fixed: a `series-candidates` subcommand, and the data home no longer fails on read. |
| F6 Verdict stance values unspecified | cosmetic | Fixed: `positive`, `mixed`, `negative` or `none`, checked by `dataset-add`. |
| F14/G10 List specs shown as Python lists | cosmetic | Fixed. |
| F15/G11 The parent's masthead was the channel name | cosmetic | Fixed: the channel is named only as the source. |
| F1 `setup-check` did not name the interpreter | cosmetic | Fixed. |
| F17 Step 8.4's coder count | cosmetic | Fixed. |
| F16/G18 Empty "today" slots on every page | cosmetic | Deferred: filling them needs a decision about what a dated note says and when a republish adds one; removing them changes the freeze format. |
| G15 Same-year price-tier videos are not linked as a series | cosmetic | Deferred: no defect; whether siblings should be related, not superseded, is a design question. |
